# Vorthrax the Crimson

A solo, CLI-based, D&D-style game where the Dungeon Master is Claude Opus 4.5
running on AWS Bedrock. The campaign premise is hardcoded (an ancient red
dragon named Vorthrax has terrorized the kingdom of Ashvale for twelve years
and the king has put a 50,000gp bounty on his head). Everything else --
NPCs, side quests, exploration, dialogue, combat -- is generated by the DM
on the fly, with persistent state across turns.

## What it does

- **Character creation**: race, class, 4d6-drop-lowest stats, a free-text
  background that the DM uses to color the campaign.
- **Dynamic world**: the DM has a campaign bible (locations, key NPCs,
  threads) and a tool-call API for mutating game state. New NPCs get a
  dossier; new places get added to the world map; nothing is invented twice.
- **D&D-lite mechanics**: real d20 rolls with modifiers, AC, HP, damage
  dice. The dice rolls are visible, not hand-waved.
- **Persistent memory**: full game state is saved to `save.json` every
  turn. The DM also keeps a journal of meaningful events that gets fed
  back into its system prompt, so it remembers important moments many
  turns later.
- **Continuity guardrail**: the DM is instructed to mutate state ONLY via
  tool calls, never via narration. So if the DM says you took 5 damage,
  the change_hp tool was actually called. No drift.

## Setup

```bash
pip install -r requirements.txt
```

Configure AWS credentials so boto3 can find them (env vars, `~/.aws/credentials`,
or instance role). Make sure your account has access to Claude Opus 4.5 on
Bedrock.

Defaults target Claude Opus 4.5 via the US cross-region inference profile in
`us-east-1`:

- model id: `us.anthropic.claude-opus-4-5-20251101-v1:0`
- region: `us-east-1`

> Note: the bare `anthropic.claude-opus-4-5-20251101-v1:0` id rejects on-demand
> calls -- you must use the `us.` (or other regional) inference-profile prefix.

Override via env or CLI flags:

```bash
export AWS_PROFILE=lytix          # or pass --profile lytix
export BEDROCK_MODEL_ID="us.anthropic.claude-opus-4-5-20251101-v1:0"
export AWS_REGION="us-east-1"
```

```bash
python game.py --profile lytix --region us-east-1
```

## Play

```bash
python game.py            # continue if save.json exists, else create a new hero
python game.py --new      # force a new campaign (overwrites save)
python game.py --save other.json
```

In-game slash commands:

| command | what it does |
| --- | --- |
| `/help` | command list |
| `/stats` | full character sheet |
| `/inventory` | inventory and equipped items |
| `/journal` | DM's running journal of events |
| `/quests` | quest log |
| `/map` | discovered (and rumored) locations |
| `/recap` | reprint the most recent DM narration |
| `/save` | save now (also auto-saves every turn) |
| `/quit` | save and exit |

Anything that isn't a slash command is sent to the DM. Be specific: speak
in quotes, describe actions, ask the innkeeper for rumors, kick down the
door, sneak past the guard, climb the cliff. The DM will roll dice as
needed.

## Files

- `game.py` -- entry point and main loop
- `dm.py` -- Bedrock Converse client + agent loop
- `tools.py` -- DM tool schemas and executors
- `state.py` -- persistent game state + system-prompt snapshot rendering
- `character.py` -- character data, creation flow, leveling
- `world.py` -- campaign bible, seed locations, seed NPCs
- `dice.py` -- dice notation parser
- `ui.py` -- terminal rendering helpers (boxes, colors, HP bar, art frame)
- `art.py` -- static ASCII art (title screen, class sigils)
- `verify.py` -- mocked end-to-end test (no Bedrock cost)

## Resuming on another machine

`save.json` lives at the repo root and is checked into git on purpose.
To move a campaign between machines:

```bash
# on machine A, after playing:
git add save.json && git commit -m "campaign progress" && git push

# on machine B:
git pull
python game.py    # picks up save.json and prompts to continue
```

The save is a single JSON file (atomic write via `save.json.tmp` → rename),
so commits are clean diffs of game state.

## Design notes

- The system prompt is **rebuilt every turn** with a fresh snapshot of
  state (player, NPCs, journal, map, current location, in-combat status).
  The model never has to remember state from message history -- it just
  reads the snapshot. This keeps the model honest and lets save/load
  work cleanly.
- Tool calls are the only way the DM can mutate state. The system prompt
  hammers this: damage, healing, XP, gold, items, movement, NPCs, quests,
  combat, conditions all require a tool call.
- The journal is the DM's long-term memory. It's instructed to write
  short entries when something meaningful happens; those entries appear
  in the snapshot every subsequent turn.
- Dice rolls are visible. The DM calls `roll_dice` with the player's
  modifier and a DC; the result is printed to the terminal so you see
  the math.

## Verifying without spending Bedrock credits

`verify.py` runs the full pipeline (character creation, every tool, save/load,
the DM agent loop, save-then-resume, and Bedrock-error rollback) against a
mocked Bedrock client. No model calls, no cost.

```bash
python verify.py
```

Should print `46 passed, 0 failed`.

## Caveats

- This is one player + one DM. No multiplayer.
- Combat is narrative + dice. There is no initiative tracker for enemies
  -- the DM handles enemy turns in prose, but rolls real attacks against
  your real AC and applies real damage.
- Costs add up. Opus 4.5 is expensive. Each turn is one or more model
  calls (more if the DM uses tools, since each tool round is a follow-up
  call). Watch your bill.
